# LENS 评审：交互设计（Interaction Design）

> 镜头来源：`interaction-design` skill（wshobson）——目的性动效（反馈 / 定向 / 聚焦 / 连续性）、
> 时长标尺（微反馈 100–150ms / 小过渡 200–300ms / 中过渡 300–500ms）、手势交互、
> 反馈模式（动作确认、成功/错误态、错误 shake）、乐观更新+回滚、动画不得阻塞输入、
> reduced-motion 必须尊重。
> 评审对象：R10 Slice A 已上线 + Slice B 进行中（`src/components/`、`src/components/cards/`、
> `shots/r10a_*` / `shots/r10b_*`）。评审标准只有一个：6–12 岁留守儿童——无成人陪护兜底、
> 几乎没有真实金钱决策经验、表达成本高、可能是第一次摸触屏设备、识字信心弱。

---

## Finding 1 — 8px 拖拽阈值会把小手的「点选」误判成拖拽，且误判后毫无反馈

- **问题 + 证据**：`src/components/cards/useDragPlay.ts` 中 `exceedsDragThreshold` 阈值固定 8px，
  与指针类型无关；一旦位移超阈值，`onClickCapture` 会吞掉随后的 click。也就是说：孩子想
  「点一张卡选中它」，手指在触屏上漂移了 9px → 卡被抬起、弹回、**没有被选中**，界面上
  没有任何解释。市场站（`MarketPanel.tsx`）的 tap-tap 是设计文档钦定的主路径
  （R10_DESIGN §6.2），这条路径对最不熟练的手恰恰最不可靠。
- **为什么对这群孩子要命**：第一次用触屏的孩子手指漂移 10px 是常态。连续两次「点了没反应」
  对一个本来就怕犯错、没人可问的孩子来说，结论不是「我手滑了」，而是「这个东西坏了 / 我不会」，
  直接弃玩。skill 原则：手势识别必须宽容，反馈必须确认动作发生过——现在两条都不满足。
- **修复**：阈值按指针类型分档：mouse 保持 8px，touch/pen 提高到 18px；再加一条时间救援：
  pointerup 时若总位移 < 26px 且按压时长 < 300ms，视为点按，放行原生 click（不吞）。
  只改 `useDragPlay.ts` 一处，全部拖拽卡受益。
- **严重度**：major

## Finding 2 — 所有花钱动作一触即不可撤销，没有「后悔窗口」

- **问题 + 证据**：全仓 grep 无 UNDO/撤销。`STALL_BUY` / `STORE_BUY` / `PAY_BUS` /
  `CHOOSE_EVENT_OPTION` 都在 drop/点按瞬间派发落账；家长站更典型：`ParentPanel.tsx` 的
  `flyCard` 在 420ms 飞行结束后直接派发 `PARENT_ANSWER`，飞行期间没有任何取消入口——
  点错图卡 = 替孩子把错误答案说出了口。
- **为什么对这群孩子要命**：这节课教的就是「花钱之前先想一想」。一个几乎没有花钱经验的孩子
  手滑买错、选错，系统立刻落账且无法挽回，学到的不是「想清楚再买」，而是「犯错会被罚」——
  与课程目标正相反。家长站选错还直接命中痛点 3：表达本来就难，系统还替他把错话说出去。
  skill 的微交互参考里明确有「乐观更新 + 失败回滚」与「点两次确认」两类后悔机制，本作一个都没用。
- **修复**（纯前端，不动引擎）：给派发加一个前端待发窗口——
  ① 家长站：飞行时间从 420ms 延长利用，飞行中卡片可再点一次取消（或在对话区旁出现一个大号
  「等等」钮，≥48px），窗口内取消则不派发；② 市场/商店/事件站试点同款模式：点买/拖放命中后，
  卡先飞到目标区并亮起一个 1.5s 的「买错了？点我撤销」chip，倒计时结束才真正 `send`；
  待发期间该卡在本地标 pending 防重复购买（`MarketPanel` 已有 boughtLen 清选中的先例可循）。
- **严重度**：major

## Finding 3 — 事件站的待翻牌堆没有任何可供性提示，孩子不知道要去点它

- **问题 + 证据**：`EventPanel.tsx` 在未翻开时只渲染一个 `Deck`，没有指令行、没有发光、
  没有脉动；`shots/r10b_event_facedown_zh_desktop.png` 里就是一张孤零零的牌背躺在大片
  白色弹窗中央。对照 `DrawTaskPanel.tsx`，抽任务站的牌堆上方有一行「抽任务卡」文字——
  同一个组件、同一个动作，一个站有提示、一个站没有。
- **为什么对这群孩子要命**：skill 的信息气味原则：可交互元素必须自证可点。家里没有大人可问、
  课堂上老师要照看一整组孩子，一个孩子在这一屏卡住，整局就停了；而且这是第 5 站，
  前面建立的操作信心会在这里第一次断裂。
- **修复**：给 `Deck` 加可选的 `hint` 行与待机动效：未翻开时顶卡套 PlayableGlow 的扫光 +
  每 2.4s 一次轻微上下浮动（transform-only，reduced-motion 下静止），文案复用现有
  「点一点牌堆」类短句（strings 已有抽卡文案可参照新增一条）。EventPanel 与 DrawTaskPanel 共用。
- **严重度**：major

## Finding 4 — 触屏没有「先看看再决定」：检视与选中被焊死，家长站一点即交卷

- **问题 + 证据**：设计文档 §1.3 承诺了「触屏长按 250ms 检视」，实现里不存在——
  `TiltCard.tsx` 对 `pointerType === 'touch'` 直接跳过倾斜，全仓也没有任何长按逻辑。
  触屏上想看清一张卡的唯一办法是点它：市场里点 = 选中并点亮投放区（尚可取消），
  家长站扇（`OptionFan`）点 = 飞入并提交答案，事件选项点 = 立即抉择。
- **为什么对这群孩子要命**：表达困难、怕答错的孩子最需要「先凑近看看、听一听，再决定」。
  现在界面把「看」和「答」绑成一个动作，探索本身变成了考试。家长站恰恰是整节课里
  专门练表达的一站，这里的误触成本最高（见 Finding 2）。
- **修复**：在 `TiltCard`/`Hand` 层补长按检视：触屏长按 300ms → 卡放大 1.15 并在上方浮出
  大字名签（复用市场已有的 `.hand-tag` 浮签机制），同时触发已有的 🔊 朗读（CardView 已支持
  speakText）；松手恢复，不改变选中态、不派发任何命令。鼠标 hover 检视保持不变。
- **严重度**：major

## Finding 5 — 手机横屏市场扇被裁切、卡名不可读，只能逐张点开「猜菜名」

- **问题 + 证据**：`shots/r10a_market_fan_zh_phone.png`：874×402 下 6 张扇卡被挤进右侧栏顶部，
  卡片上缘被面板裁掉，相邻卡名互相压叠（只能看到「菜谱…」碎片），只有被选中的那张能在
  下方文字行里读到名字。设计文档 §6.1 当时把这列为待拍板风险，兜底方案是「选中时浮出名签」，
  但截图里未选中的卡连名签都没有——孩子要比较「买哪个」，必须逐张点开串行读取；
  露出可点带也明显窄于令牌规定的 48px（`--tap-min-size`）。
- **为什么对这群孩子要命**：比较选择正是消费课的核心训练。把「并排比一比」降级成
  「逐个点开猜」，对识字慢的孩子等于把决策题改成了记忆题。设计文档 §6.1 本来就预留了
  官方备选：小屏退回网格——触发条件（截图验收不通过）现在已经满足。
- **修复**：手机横屏（phone-land）下市场/商店的扇改为紧凑网格：`Hand` 已有 `layout='free'`
  模式可复用，或在该断点下让扇展开为两行不重叠排布；每卡露出完整名牌带且可点区 ≥48px。
  桌面/平板保持扇形不变。拖拽与 tap-tap 逻辑零改动（拖拽源仍是同一批 CardView）。
- **严重度**：major

## Finding 6 — 「钱不够」的反馈三站三种样：事件站是点下去毫无反应

- **问题 + 证据**：市场站买不起的卡：可选中 → 显示「钱不够」文字行，拖过去还有 shake；
  事件站（`EventPanel.tsx`）花钱卡直接 `disabled={!playable}` —— 点下去没有 shake、
  没有动静、没有任何反馈（disabled 按钮在浏览器里就是静默的）；公交站则是欠费文案。
  同一个概念（钱不够）在三个站给孩子三种完全不同的回应，其中一种是「无回应」。
- **为什么对这群孩子要命**：skill 要求反馈模式一致且优先用动效而非文字（错误 shake 是其
  参考文件里的标准件）。「点了没反应」对低识字孩子最致命——他读不懂灰字的原因，
  只会反复戳，或者认定游戏坏了。市场站的做法（可点、给 shake、金币区给反应）才是对的，
  只是没有贯彻到所有站。
- **修复**：事件花钱卡去掉 `disabled`，改为与市场同构的「可点不可打」：点按 → 卡身 shake
  180ms + 价格宝石红闪一次 + 金币 HUD bump；命令门控仍读 `availableCommands`，不发命令。
  顺带把市场站那行「钱不够」文字保留为第二通道即可，不必删。
- **严重度**：minor

## Finding 7 — 家长站自由输入默认孩子会拼音打字，语音钮是个假按钮

- **问题 + 证据**：`ParentPanel.tsx` 的自由回答只有文本输入框；对 6–9 岁孩子，
  打出中文 = 先会拼音输入法，这是比「表达需求」高得多的一道门槛。旁边的 🎤 语音钮：
  真对话模式下点它只往聊天气泡里塞一条提示文本（`local: true`），离线模式下直接派发一个
  预设的 `mode:'voice'` 答案——两种模式下它都不录音，但长相完全像一个录音按钮。
- **为什么对这群孩子要命**：这一站就是为痛点 3（表达成本高）设的。唯一像样的「开口说」
  通道是个假的，孩子点下去以为自己说了话，实际什么都没发生——这是在教他「表达没有用」。
- **修复**（前端可做）：① 浏览器支持 Web Speech API 时，把语音钮接真听写：识别文本实时
  回填输入框，孩子看一眼再点「发送」——识别结果可见可改，恰好练表达；② 不支持时，
  语音钮改为诚实行为：点它 = 把当前问题用已有 TTS 朗读一遍 + 展开图卡扇，
  图标/文案不再暗示录音。图卡主路径不动。
- **严重度**：minor

## Finding 8 — 站点弹窗无入场过渡，面板凭空出现/消失，孩子跟丢「我在哪」

- **问题 + 证据**：`StationPopup.tsx` 及其 CSS 没有任何入场动画（grep `animation/transition`
  在弹窗相关样式中无命中）：点完一站，下一站的弹窗瞬间整屏替换；底栏手牌、棋盘棋子同时变化。
  skill 的定向（orientation）原则要求过渡交代元素从哪来、到哪去。
- **为什么对这群孩子要命**：6–8 岁孩子的空间连续性感知弱，整屏瞬时替换容易产生
  「刚才的东西去哪了」的迷失感，尤其每圈 8 站 × 3 圈 = 24 次切换，累积成疲劳。
  这也是全作少数「所有站都中招」的通病。
- **修复**：给 `.popup` 加 240ms 入场（opacity + translateY(8px)→0 + scale .98→1，
  `--ease-out`），退场 150ms 淡出；reduced-motion 下只留 120ms 淡入。
  纯 CSS、一处修改、全站生效，时长落在 skill 的小过渡档（200–300ms）内。
- **严重度**：minor

## 已经做得好的（不要改坏）

- **双通道等价贯彻得彻底**：每个拖拽动作都有 tap-tap 与键盘路径，投放区本身就是 ≥48px
  的大按钮，选中卡时投放区会「武装」亮边——这是对低龄用户最正确的手势降级设计。
- **错误反馈用动效不用文字**：无效投放 = 弹簧弹回 + 180ms 轻 shake，不弹任何报错文字
  （市场站），符合低识字友好与无惩罚基调。
- **防重复购买的细节**：买完自动清空选中（`MarketPanel` 里专门处理了「买了鱼出现两次」
  的历史反馈），且默认预选中第一张卡，第一步该点哪从不含糊。
- **成功反馈链完整**：买入 → PlaySpark 迸溅 + CoinCounter 滚动 + 浮動 ±N，
  动作—反馈对应关系清楚；家长站真对话有「思考中」气泡，等待不空白。
- **求助牌随时可举**（底栏常驻，HelpCard 给「缺哪些菜 / 还剩几币 / 本站能做什么」）——
  这是全场对痛点 3 最实在的承接，建议在后续轮次里保持常驻位置不被手牌挤走。
- **无障碍底盘扎实**：弹窗焦点陷阱、Esc 取消选中、aria-live 播报回合与选中信息、
  reduced-motion 下翻牌/弹回/计数全部有降级档，拖拽 rAF 静止自停。
